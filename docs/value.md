# FinOS AI · 价值量化说明

> 本文说明 FinOS AI 在企业金融资料研判中的价值来源与度量方法。文中的对照数值是**示范假设**，用于说明度量口径；真实收益取决于资料规模、行业与部署方式，建议按本文方法自行测量。

## 一、要解决的问题

企业授信、尽调、经营分析的核心工作是「把散落的资料变成可核验的判断」，而人工处理存在三类损耗：

1. **搬运损耗**：PDF/Word/Excel/图片中的数字靠人工誊抄，慢且易错。
2. **追溯损耗**：结论说完就散，无法回答「依据哪份资料、哪条规则、哪个位置」。
3. **一致性损耗**：同一套准入制度在不同人手里阈值口径不一，漏检与标准漂移。

## 二、系统如何缩短链路

| 环节 | 人工做法 | FinOS AI 做法 | 可度量指标 |
| --- | --- | --- | --- |
| 资料解析 | 逐个打开、人工定位 | 文本/OCR/表格结构化，保留行号与坐标 | 单份解析耗时 |
| 事实抽取 | 手工誊抄并核对 | 模型抽取 + 原文逐字引用 | 抽取准确率 / 召回率 / 引用有效性 |
| 规则匹配 | 翻制度、凭经验 | 71 条模板 + 确定性引擎判定 | 规则命中一致率（可复现） |
| 风险研判 | 人工归纳、口径不一 | 事实 + 规则 + 影响 + 复核状态 | 待核验风险数量 |
| 复核留痕 | 口头/分散记录 | 人工核验闭环 + 操作留痕 | 复核覆盖率 |
| 交付 | 手工整理报告 | 一键导出 Markdown/Word/PDF | 报告生成耗时 |

## 三、量化框架（建议按此测量）

- **效率**：同一批 N 份资料，人工整理 vs 系统辅助（含人工复核）的总耗时。
- **覆盖**：抽取并复核的关键指标条数 / 应覆盖指标条数。
- **质量**：抽取准确率、召回率、引用有效性（`npm run ai-eval`）；规则命中一致率（`npm run benchmark`）。
- **可追溯**：可定位到原文位置的事实占比 = 100%（系统强制事实携带引用）。

### 示范对照（假设值，非实测）

| 指标 | 人工基线（假设） | 系统辅助（假设） |
| --- | --- | --- |
| 10 份资料关键指标整理 | 约 4–6 小时 | 约 0.5–1 小时（含复核） |
| 引用可追溯比例 | 视记录习惯，通常不完整 | 100%（强制引用） |
| 规则口径一致性 | 依赖个人 | 确定性引擎，跨人一致 |

> 上表仅用于说明度量口径。请在真实项目上按第三节方法测量并替换。

## 四、与「和 PDF 聊天」类方案的差异

- **确定性**：规则命中由纯函数判定，同一输入得到同一结论，可复现、可审计。
- **证据优先**：结论必须回到原文引用与位置，避免编造。
- **人机闭环**：候选风险必须人工核验才算数，操作留痕。
- **治理内建**：组织角色、项目授权、数据密级、复核队列、模型评测、审计开箱可用。

## 五、如何复现证据

```bash
# 确定性规则引擎评测（不调用模型）
npm run benchmark

# 事实抽取真实评测（需已配置模型）
npm run ai-eval
```

结果分别见 `docs/benchmark.md` 与 `docs/ai-eval.md`。

# FinOS AI 产品审查与强化路线（2026-08-30）

## 审查范围

本轮从首次进入系统开始，按真实用户路径验证了：项目创建、模型配置与连通测试、规则录入、企业资料上传、AI 事实抽取、确定性规则命中、Agent 运行、风险登记、流程任务、研究底稿、智能研判助手、全局搜索、通知和工作区管理。同时执行了 TypeScript、ESLint、前端契约、规则引擎、Python 后端/AI、生产构建和端到端测试。

| P1 | Agent 历史输出转风险或任务时默认归到第一个项目 | 运行记录没有项目 ID 和企业名称 | 新运行记录保留项目归属；旧记录无归属时阻止直接转换并提示重新运行 |

## 第二轮多项目隔离复核

第二轮使用两个企业项目进行交叉验证。项目选择现在由资料研判、Agent 中心、智能助手和投研中心共享；切换项目会同步切换可用资料、项目风险、对话历史与研究底稿。规则库仍作为工作区全局受控规则使用，并在界面明确标记为“全局规则”。风险中心和流程中心继续提供跨项目总览，但新增任务和 Agent 产出都保存稳定的项目 ID。

兼容策略：旧版 Agent 运行、对话或底稿没有项目 ID 时，仅在工作区只有一个项目的情况下显示；多项目环境下不自动猜测归属。这样可以避免为了兼容旧数据而把结果错误归给另一家企业。

## 已验证的业务主链路

1. 用户创建企业经营或融资研判项目。
2. 在模型中心配置自己的 OpenAI、DeepSeek、Qwen、Claude、Ollama 或兼容网关。
3. 录入结构化业务规则并上传企业资料。
4. 模型抽取带原文引用的事实，确定性规则引擎独立计算命中结果。
5. Agent 汇总资料、规则、风险、缺口与人工复核清单。
6. Agent 输出可转为待核验风险和人工流程任务，且不会重复创建。
7. 投研中心生成有来源边界且绑定项目的底稿，智能助手只基于当前企业项目继续研判。

## 后续强化计划

### 近期：可用性与可追溯性

- 为项目、资料、风险、流程任务补齐编辑、归档和细粒度删除能力。
- 让风险直接引用资料事实、原文位置、命中规则和 Agent 运行 ID。
- 增加项目时间线，把上传、分析、核验、规则变更和审批动作串成审计轨迹。
- 为模型中心增加连接失败诊断、超时/限流提示和调用用量视图。

### 中期：企业级流程

- 建立组织、成员、角色与项目权限模型，区分分析、复核、审批和管理员。
- 支持流程模板、节点条件、退回、会签、SLA 和导出审计记录。
- 增加可信外部数据源连接器，并对每条外部事实保留来源、时间和快照。
- 引入异步文档队列、OCR、批量上传、失败重试和大文件对象存储。

### 长期：AI + 金融能力

- 建立行业化规则包与评测集，覆盖授信预审、经营风险、供应链、投研和合规场景。
- 对抽取、规则匹配、风险归因和报告生成分别做准确率、召回率与幻觉率评测。
- 增加多 Agent 编排、工具权限、人工批准点、可回放运行记录和成本预算。
- 打通企业财务系统、工商/司法/舆情/行情数据，在严格来源治理下形成持续风险监测。
